# 第七版：演示文稿与信息图

## 使用

笔记本右侧工作室 → 演示文稿 / 信息图。选择可用资料、笔记或研究报告，填写用途、受众和主题。笔记与报告正文标为用户观点，其原始引用单独取证，不视为新的独立来源。

1. 生成大纲。演示文稿默认8页，可请求5–15页，依据不足时可以少于目标页数；信息图选要点概览、双栏对比或流程步骤，选择方向与密度。
2. 编辑标题、观点、要点、顺序、版式与备注，核对引用。自动保存显示保存状态；版本冲突不会覆盖其他标签页的修改，需重新加载并合并。
3. 确认大纲后生成页面。后台逐页生成，全部通过结构、空间和证据复核后整体发布。失败可重试，成功页复用；也可填写要求只重新生成指定页。
4. 切换简洁商务、教学讲解、研究汇报模板和主题色。修改事实后显示“内容已修改，引用需核对”。编辑后更新预览；缩略图、缩放与全屏播放使用服务端实际渲染页面。
5. 导出PPTX/PDF，信息图导出PNG/PDF。导出固定使用提交时的版本，随后编辑不会改变已排队文件。历史版本可查看并下载已生成文件。

没有模型密钥时可选择手动创建，填写正文后预览、导出。手动内容不会伪装为模型生成或经过资料核验。

## 升级与部署

先按部署文档备份数据库和对象存储，然后在项目目录执行：

```sh
docker compose stop web api worker beat
docker compose build
docker compose run --rm migrate
docker compose up -d
docker compose logs --tail=100 migrate api worker beat
```

迁移008新增成果、不可变版本、阶段任务和对象清理账本四张表，保留原有数据。API文档 `/api/docs` 中的“演示文稿与信息图”包含接口契约。预览、历史版本和文件下载均验证用户和笔记本归属。

镜像安装Noto Sans CJK字体、Cairo及Node.js；构建阶段安装固定版本PptxGenJS。无需PowerPoint、桌面软件或付费图片服务。字体使用SIL Open Font License，分发时保留镜像内字体版权文件（Debian `/usr/share/doc/fonts-noto-cjk/copyright`）。PPTX不嵌入字体，打开它的电脑应安装同名字体；PDF嵌入字形，PNG不依赖客户端字体。

|变量|默认值|说明|
|---|---|---|
|VISUAL_USER_CONCURRENCY|2|同一用户并行任务，上限4|
|VISUAL_DAILY_JOBS|50|创建/操作各自的24小时限流，重试计入操作额度|
|VISUAL_MAX_TOKENS|12000|每次结构化生成最大输出|
|VISUAL_RENDER_TIMEOUT|90|PPTX进程超时秒数|
|VISUAL_FONT_PATH|镜像内Noto字体集合|文字测量字体，索引2为简体中文；更换时须同步渲染器字体名称|

聊天与向量调用复用既有服务端配置。每页生成最多一次格式修复，另一次独立证据复核；整次任务最多人工重试3次。模型超时复用GENERATION_TIMEOUT_SECONDS，任务软/硬时限240/270秒，租约300秒。取消停止后续调度，已发出的外部请求可能仍计费。

## 内容、引用与渲染

受控页面支持封面、章节、要点、对比、流程、图表、总结与来源及表格。资料片段由后端选择，模型只能返回本次证据编号。来源版本固定；生成期间来源变化取消发布，不静默更换依据。历史成果保留旧片段；更新和删除分别提示，删除来源禁用原文跳转。

网页PNG与PDF来自同一经过字体测量的场景，PPTX由相同场景导出可编辑文字、形状及原生条形图。备注保存完整引用与原文；PDF每页的文本注释保存同一份来源详情。部分PDF阅读器不展示注释面板，此时可在应用查看完整引用。

图表目前限条形图，支持原值、求和、差值和比例。后端验证原文数值、单位、时间与引用，再用Decimal计算并保存方法；模型另行复核配对语义，不替代人工审核。不补齐缺失数据。表格为可编辑基础形状和文字，不是PowerPoint原生表格对象。

固定字号，放不下会明确拒绝预览/发布，要求缩短或拆页。上限15页、每页6要点、表格4列6行、每页10引用、500个自动保存版本。达到版本上限需创建新成果。

临时目录随正常结束清理，中断任务由租约回收。取消/删除对象由持久化账本重试清理；失败渲染的成功分段保留一天供重试。成果删除不影响其他成果文件。备份工具已覆盖新增文件。

## 边界

不支持任意拖拽、外部图片、生成图片、复杂动画和自定义执行代码。模型复核有误判可能，关键结论与数值须人工核对。长资料采用有界证据选择，不保证穷尽全文。PPTX原生图表与PDF可能有细微轴线/标签差异，核心内容、版本与数值相同。任务失败不覆盖确认的大纲或已有页面。

协议模型替身仅验证异常与权限，不作为真实模型质量证明。实际调用与文件检查见VERIFICATION_V7.md。

参考：[PptxGenJS文字](https://gitbrent.github.io/PptxGenJS/docs/api-text/)、[讲解备注](https://gitbrent.github.io/PptxGenJS/docs/speaker-notes/)、[图表](https://gitbrent.github.io/PptxGenJS/docs/api-charts.html)、[CairoSVG](https://cairosvg.org/documentation/)。
## 供应商结构化输出选项

`VISUAL_JSON_MODE=true` 和 `VISUAL_REASONING_EFFORT=low` 已用当前阶跃星辰 `step-3.5-flash` 接口验证。它们仅用于图文生成和支持性复核，不改变聊天、学习或音频的调用参数。切换供应商时，若不支持这些字段，分别设为 `false` 和空值；后端仍执行完整的结构、引用和排版校验。服务端缺省不发送这两个可选参数。

生成请求只传递本次证据编号、类型和正文。笔记、报告中遗留的引用编号仅作为原有标记处理，不混入本次编号集合；原始快照和引用关联保持不变。信息图请求固定为一张画布，单页重生成固定为指定页面。官方参数说明：[Chat Completion](https://platform.stepfun.com/docs/zh/api-reference/chat/chat-completion-create)、[Step 3.5 Flash](https://platform.stepfun.com/docs/zh/guides/models/step-3.5-flash)。

支持性复核按每页实际引用的证据分别检查，不能借用未引用页面的材料。正常的本成果受众、用途和目录说明按生成参数核对，不伪装成原始资料结论；事实与备注仍须来源支持。结构或证据复核失败，最多进行一次带错误反馈的修复，仍不合格则保留失败状态。人工核对和编辑大纲是正常流程，模型复核不能取代人工验收。

中英文混排保留英文标识、IP地址和引用编号的完整性，中文句末标点随前文换行。不可容纳的超长标识明确提示更换版式或精简，不裁切正文。
