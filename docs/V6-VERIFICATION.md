# 第六版实际验证记录

验证时间：2026-10-08 至 2026-10-09（香港时间）。现有项目继续使用 Next.js / FastAPI / PostgreSQL + pgvector / MinIO / Redis + Celery；没有新建云资源或发布公网。

## 检查到的基础与修复

开始时本机数据库停留在005，代码已有多来源导入工作但尚未完成实际升级验证。本轮补齐第五版回归并依次升级006、007。升级前暂停写入，备份数据库及整个私有对象存储卷。原有3个用户、3个笔记本、5份资料、30条消息、13组学习成果、2个音频概览及1个已合成音频的记录保留；本轮真实验证使用独立验收账号和笔记本。

发现并修复：待确认状态超过旧任务字段长度；旧PDF导出位置格式兼容；测试夹具未设置活动版本；网页定义标题提取遗漏；研究上下文缺少相邻例外条目；入库保留记录后失败缺少独立重试入口；旧报告追问未提醒资料更新。备份工具补齐全部历史来源版本与音频对象。

## 自动测试

按模块分批验证，共覆盖129个测试案例：旧版77、第五版34、第六版18。不是一次运行全绿的统计：旧版首轮75通过、2失败；修复后第二/四版相关21项通过。第五版34项通过；最后第六版18项在隔离栈中通过（28.72秒）。前端生产构建和TypeScript检查通过。

隔离测试使用真实HTTP、数据库、向量列、对象存储、Redis及Worker，外部聊天/向量/TTS使用明确标识的协议夹具。真实供应商调用另见下一节，不能将协议测试等同于生成质量测试。

覆盖的关键行为：

- 注册、账号隔离、PDF上传/重试/删除、历史问答、引用、笔记并发保存、学习进度及测验评分、音频任务恢复。
- DOCX标题/列表/表格、UTF-8/GB18030/UTF-16中文、TXT/Markdown、文本版本及引用快照。
- 中文PNG、扫描PDF、混合PDF使用真实本地Tesseract识别；部分OCR失败/确认、仅失败页重试、人工修正及旧原图关联。
- 网页登录/验证/无正文拒绝，私网地址、云元数据、重定向和DNS固定连接边界。
- 搜索规范链接去重、缺少凭证不返回假结果、摘要与正文分离、预览快照复用、导入幂等、报告幂等与独立版本。
- 其他用户不能读取研究任务/候选预览/正文快照/报告/导出，不能触发获取或删除。
- 取消运行中的获取后迟到结果不能发布；删除笔记本阻止旧任务运行；删除研究保留已导入来源及已保存报告；日配额阻止实际搜索调用。
- 非法引用、伪造逐字引文、错误结构拒绝；取消的有效预览可恢复且无需再次获取。

复现：

```sh
docker compose -p narcissus-test -f compose.yaml -f compose.test.yaml up -d --build
docker compose -p narcissus-test -f compose.yaml -f compose.test.yaml run --rm tester
```

测试配置只用于独立的 `narcissus-test` 项目。不要对已有业务库运行测试。

## 真实服务与浏览器验证

使用已配置StepFun独立搜索、StepFun聊天和阿里云向量服务。没有提供固定搜索结果或固定报告作为产品回退。

研究问题为“Python 官方中文文档 ipaddress 私有地址 is_global”。实际搜索一次得到9个去重结果，保存了原查询和调用信息。界面显示搜索服务摘要及“发布时间未知”，没有将供应商索引时间误当发布时间。

通过受限网页获取导入搜索结果中的 Python 中文索引页，另外明确选择已有的 ipaddress 中文API参考。预览与正式入库的获取时间一致，没有二次抓取替换正文。早期另一个公开中文问题的政府网页获取超时被标记为失败，没有以搜索摘要代替正文。

保存3个独立报告版本。第三版首次返回无效引用结构，任务失败且正文为空；点击等效重试接口后成功，前两版不受影响。报告固定记录原始资料ID、版本、获取时间、原URL及实际引用。生成和独立复核有真实用量记录。

人工抽查：报告核心结论关于共享地址空间100.64.0.0/10的两个属性均为False，引用确实对应原文第55段。网页预览显示“第55段”，没有编造PDF页码；页面自动滚动到对应段落并突出显示。来源版本2可用，版本1快照仍可访问。

实际追问“根据原文，100.64.0.1 的 is_private 和 is_global 分别是什么？”得到流式回答：两者均为False，分别附真实原始网页引用。报告自身没有被作为额外资料检索。

Markdown和DOCX下载成功；解析DOCX内部文档确认标题、原文引用、来源URL和获取时间存在。报告编辑后显示修改提示、引用保留，重复旧版本保存返回409。浏览器验证工作室入口、历史任务、结果/来源选择、报告打开、阅读预览及引用原文定位。

随后实际重启数据库、对象存储、Redis、API、Worker、beat及前端。重新登录后，旧报告正文哈希和两个历史快照哈希完全一致；3个报告版本、来源选择、人工编辑内容和新问答消息仍存在。数据库为007 (head)，原金融PDF仍为ready/活动版本2。

## 不能夸大的部分与已知限制

- 语义复核是模型审查，不是事实正确性的证明。人工抽查仍发现个别推断分类及“片段未覆盖哪些规则”的表述不够准确；已增加定义相邻段落、完善修复反馈和复核规则，但不能保证自动清除所有这类问题。核心被抽查的共享地址规则有直接原文支持；不能据此声称整篇报告每句均已通过人工核验。
- 普通网页获取在当前网络中会受站点连接超时影响；支持安全失败、重试和粘贴正文，不保证每个搜索结果均可读。
- 没有供应商原生时间/语言过滤；没有扩展检索词、自动多轮研究或完整转载关系识别。界面说明了这些范围。
- OCR、学习及音频原有链路本轮做了协议/回归验证；没有再次对所有旧资料付费生成全部学习成果和音频，也没有全浏览器、移动设备、负载或公网HTTPS实测。
- 本地迁移和重启恢复已实测；完整灾难备份恢复没有在本轮重新执行。升级前备份保留在私有工作目录，交付包不含业务数据与真实凭证。
