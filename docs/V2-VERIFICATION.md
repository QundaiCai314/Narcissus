## 真实服务验证

正式应用实际使用阶跃星辰 `step-3.5-flash` 与阿里云百炼北京工作空间 `text-embedding-v4`（1024 维）。两家密钥只配置在本机服务端 `.env`，不在源码、截图或压缩包内。小样本不是客户私密资料。

使用两份自建中文 PDF：项目方案有两页，分别说明第一阶段预算三百万元、第二阶段计划于二零二七年完成；预算复核文件写五百万元，并注明未解释差异或批准状态。另创建一条“优先改善步行空间”的个人建议。

实际通过：

- 两份 PDF 经真实 Worker、真实向量 API 完成解析入库。
- 两份自动导读含 3–5 个建议问题、真实页码与来源关联。
- 仅选择项目方案，预算回答为三百万元并引用第一页；阶段完成时间回答为二零二七年并引用第二页。
- 对“火星殖民地的人口是多少”返回“当前资料中未找到足够依据”。
- 混合总结说明三百万元与五百万元的冲突，各自引用原文；个人建议单独标为“来自用户笔记（未经原始资料核验）”。
- 最初真实总结因混用原文 / 笔记引用及空引用而被后端拒绝。补充明确输出分块规则与错误反馈后，同一总结手动重试在第一次尝试完成；没有绕过校验或替换固定答案。
- 实际导出 Markdown 与 DOCX，重新打开 DOCX 包检查标题、列表、来源章节与原文文本。

小样本验证不等于全面中文语义评测。模型仍可能出现语义偏差；格式校验只能保证来源编号有效和类型边界，不能自动证明所有结论都被引用蕴含。
